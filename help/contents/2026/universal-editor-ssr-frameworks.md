# 具備通用編輯器和現代SSR架構的快速可編輯網站

現代網路團隊想要自由的Headless與現代JavaScript架構，而不需要犧牲行銷人員的內容編輯。 在這場會議中，我們展示Adobe Experience Manager Universal Editor和現代伺服器端轉譯(SSR)架構（例如React和Next.js樣式設定）如何提供快速、搜尋引擎最佳化(SEO)的網站，讓作者仍可透過視覺化方式編輯。 我們說明如何將通用編輯器匯入框架式應用程式、SSR如何影響效能和Core Web Vitals，以及如何建構元件，讓作者可以安全地更新體驗而不會破壞前端。 如果您正在規劃或更新Adobe Experience Manager (AEM)或Edge Delivery Services (EDS)專案，此網路研討會會提供實用的藍圖，您可立即使用。

>[!VIDEO](https://video.tv.adobe.com/v/3491408/?learn=on&enablevpops)

## 重點提要

* **何時使用標準EDS網站與自訂SSR架構**
我們瞭解為什麼標準Adobe Experience Manager Edge Delivery Services (EDS)網站是大多數專案的最佳預設值，以及將Universal Editor圖層化至現有應用程式（例如商店或入口網站）而非重建是否有意義。

* **Universal Editor如何同時插入EDS和現有的架構**
我們看到Universal Editor如何適應典型的AEM EDS設定，以及在將其連線到已在生產中使用的React或Next.js樣式SSR應用程式時如何套用相同的概念。

* **SSR，計算平衡EDS預設與效能及SEO需求**
我們瞭解了何時可仰賴EDS預設值，以及何時真正需要自訂伺服器端轉譯(SSR)來取得特定體驗，包括產品詳細資料或登陸頁面等高價值頁面對SEO和Core Web Vitals的影響。

* **為開發人員和行銷人員創作時未破壞您的應用程式模式**
我們探索了元件和內容模型模式，讓開發人員能夠保持乾淨的可維護程式碼基底，同時為作者提供安全的內容內編輯能力，無論是在標準EDS網站上還是與現有架構整合。
